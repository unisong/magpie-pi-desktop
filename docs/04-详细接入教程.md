# Pi-Desktop 接入 Magpie：详细步骤

按顺序做下面 7 步，每一步都写了"怎么做"和"做完应该看到什么"。整个过程不改 Codex 的 `~/.codex/config.toml`，也不改 Magpie 的供应商、分组和其他插件。

文中的占位符，用的时候换成你自己的：

- `<本仓库>`：你克隆本仓库的文件夹。
- `<Magpie 安装目录>`：`magpie.com` 所在的文件夹。
- `<Pi-Desktop 安装目录>`：Pi-Desktop 的安装文件夹。
- `%USERPROFILE%`：你的用户文件夹（例如 `C:\Users\<用户名>`）。它不用替换，可以原样粘贴进"选择文件夹"窗口的地址栏；在 PowerShell 里写作 `$env:USERPROFILE`。

**已经按旧教程（0.1.1 或 0.1.2，装 `.piplug` 的那一版）接好的**：只做 [从旧版本升级](#从旧版本升级) 那一节。

## 它是怎么跟着 Magpie 变的

| 部件 | 在哪 | 作用 |
|---|---|---|
| Magpie 插件（文件夹 `<本仓库>\packages\pi-desktop`） | Magpie | 在 Magpie 的 Agent 页加一行 Pi-Desktop：它有自己的网关密钥，用量、路由规则和可见模型都按它单独算 |
| 插件文件夹 `%USERPROFILE%\.config\magpie-pi-desktop\plugin`（里面只有一个 `manifest.json`） | Magpie 写，Pi-Desktop 读 | 这是一个 Pi-Desktop 插件。它声明 "Magpie" 这个 AI 服务、地址 `http://127.0.0.1:3425/v1`、Magpie 当前给 Pi-Desktop 的全部模型和每个模型的推理等级 |

- Pi-Desktop 这一行在 Magpie 里是 **已连接** 时，Magpie 的模型一有变化（加减供应商、增删模型、改可见模型、换端口），Magpie 就自己重写这个 `manifest.json`。
- Pi-Desktop 把这个文件夹当作"本地插件"加载，**每次启动都重新读一遍**。所以 Magpie 里改了模型，重启 Pi-Desktop 就跟上了，不用再打包、重装。
- Pi-Desktop 限制每张服务卡片最多 64 个模型，超过时会多出 "Magpie 2"、"Magpie 3"…
- 这个插件不带任何代码，只有一个 `manifest.json`。它只申请一项权限：**将服务添加到模型列表**。

两边靠一个密钥对上：**`magpie-pi-desktop-app`**。Pi-Desktop 每次请求都带上它，Magpie 就知道这是 Pi-Desktop 发来的。

## 第 0 步：准备

1. **Magpie 在运行**：任务栏右下角的托盘区有 Magpie 图标。
2. **Pi-Desktop 0.22.0 或更新**（只在 0.22.0 上验证过）。
3. **Node.js 22.5 或更新**（只有自检脚本用到）：在 PowerShell 里执行 `node -v`，应显示 `v22.5` 以上。
4. **让 `magpie` 命令可用**。Magpie 的命令行不在 PATH 里，先在 PowerShell 里执行（只对当前窗口有效）：

   ```powershell
   Set-Alias magpie "<Magpie 安装目录>\magpie.com"
   magpie --version
   magpie ls
   ```

   - `magpie ls` 列出所有 Agent，其中有一行 Codex，后面是它当前用的模型和 effort。
   - 每条命令输出开头的 `plugin: …` 几行是你自己的其他插件打印的，不用管。
   - PowerShell 可能把 `—` 显示成 `�?`，这只是控制台编码问题。

## 第 1 步：把插件加进 Magpie，并确认它加载成功

Magpie 直接读文件夹 `<本仓库>\packages\pi-desktop`，不复制它，所以不要移动或删除它。

1. 打开 Magpie 窗口，左侧 **扩展** 分组下点 **插件**。
2. 点页面顶部的 **已安装** 标签（另外两个标签是 **内置** 和 **发现**）。
3. 在列表里找名称为 `pi-desktop`、带 π 图标的那一行，按看到的情况处理：

   | 看到的情况 | 意思 | 怎么做 |
   |---|---|---|
   | 没有这一行 | 插件不在 Magpie 里 | 按下面"添加插件"做 |
   | 下面写着"把 Pi-Desktop 加到 Agent 页"，没有红字 | 加载成功 | 直接做第 4 小步确认 |
   | 下面有红字（`Agent 没有加载：…` 或 `没有加载成功：…`） | 插件文件有问题 | 看最后的排错表 |
   | 下面写着"关闭" | 插件被停用了 | 点这一行的 **启用** |

4. 下面三项都满足，才算加载成功：
   - **已安装** 里 `pi-desktop` 这一行下面写着"把 Pi-Desktop 加到 Agent 页"，没有红字。
   - 左侧 **使用** 分组下点 **Agent**，列表里出现 **Pi-Desktop**（π 图标），状态是 **未连接**。
   - 在 PowerShell 执行 `magpie ls`，有这一行（路径太长时末尾会被截断）：

     ```
     Pi-Desktop        provider —        ~\.config\magpie-pi-desktop\plugin\manife…
     ```

**添加插件**（"已安装"里没有 `pi-desktop` 时）：

1. 点 **发现** 标签，往下滚到 **已有想装的？** 这一栏。它是一个输入框，提示文字是"npm 包名、GitHub 仓库（github:owner/repo）或本机文件夹"。
2. 点输入框右边的文件夹图标（鼠标停上去显示"选择本机上的一个文件夹"），选 `<本仓库>\packages\pi-desktop`。没有这个图标时，直接把这个路径粘贴进输入框。
3. 点 **安装**。按钮先变成 **安装中…**，完成后页面提示 `<本仓库>\packages\pi-desktop 已安装`。
4. 回到 **已安装** 标签，按上面第 3、4 小步核对。

**发现** 页提示"无法加载插件：…"或一直在加载时，看不到 **已有想装的？** 这一栏。这时用命令行添加，效果一样：

```powershell
magpie plugin add "<本仓库>\packages\pi-desktop"
```

用命令行添加后，如果过一会儿 Magpie 窗口的 **已安装** 里还没有这一行，在托盘区右键 Magpie 图标，选 **退出 magpie**，再打开 Magpie。退出期间网关会停，正在跑的 Codex 任务会断开，挑空闲时做。

## 第 2 步：在 Magpie 里接入 Pi-Desktop

1. 先给 Codex 的现状拍一份快照，第 6 步用它确认接入没有影响 Codex：

   ```powershell
   cd <本仓库>
   node verify\codex-invariants.mjs snapshot verify\before-connect.json
   ```

   预期输出 `snapshot written: verify\before-connect.json`。快照只记录模型名、文件指纹（哈希）和几条只读命令的输出，不含任何密钥。
2. Magpie 左侧 **使用** 分组下点 **Agent**，找到 **Pi-Desktop** 这一行，点 **接入**。
   - 命令行等价操作：`magpie pi-desktop-app provider magpie`
3. 预期：这一行变成 **已连接**。
4. 确认 Magpie 写出了插件文件夹：

   ```powershell
   node -e "const m=require(process.env.USERPROFILE+'/.config/magpie-pi-desktop/plugin/manifest.json'); console.log(m.version, m.magpie.baseUrl, m.magpie.apiKey, m.contributes.providers.map(p=>p.name+' ('+p.models.length+')').join(', '))"
   ```

   应打印类似下面这一行。模型数和卡片数以你的 Magpie 为准：

   ```
   0.2.0 http://127.0.0.1:3425/v1 magpie-pi-desktop-app Magpie (64), Magpie 2 (33)
   ```

   - 报 `Cannot find module …manifest.json`：文件没写出来。看排错表"接入后没有 manifest.json"那一行。

这一步做了什么：Magpie 把一份完整的 Pi-Desktop 插件清单写进 `%USERPROFILE%\.config\magpie-pi-desktop\plugin\manifest.json`，里面是网关地址、密钥名和模型清单（含每个模型的推理等级和默认档位）。Magpie 在自己的 `applied.json` 和 `stash.json` 里记下 `pi-desktop-app` 这一项，不碰 Codex 那一项。之后只要这一行保持 **已连接**，模型一变 Magpie 就重写这个文件。

默认推理等级的规则和 Magpie 给 Codex 用的一样：模型支持 high 就用 high；不支持就取比 high 高的最近一档（例如只有 xhigh、max 的模型用 xhigh）；再没有就取比它低的最近一档。Magpie 没给出推理等级的模型保持 Pi-Desktop 的通用设置：所有档位都能选，默认 off。

## 第 3 步：在 Pi-Desktop 里加载这个文件夹

这一步只做一次。以后模型变了不用再做。

1. 打开 Pi-Desktop，左侧点 **扩展**。
2. 点页面顶部右边的 **⋯** 按钮（"更多操作"），在弹出的菜单里点 **加载本地插件**（在 **安装插件包** 的下面一项）。
3. 弹出 Windows 的"选择文件夹"窗口。把下面的路径粘贴到窗口顶部的地址栏里按回车，再点 **选择文件夹**：

   ```
   %USERPROFILE%\.config\magpie-pi-desktop\plugin
   ```

   要选的是 `plugin` 这个文件夹本身，不是它上一层的 `magpie-pi-desktop`，也不是里面的 `manifest.json`。
4. 弹出确认框，标题是 **加载 Magpie Gateway？**，正文是"这是来自本机文件夹的开发插件。请确认它可以执行的操作——在你同意前不会加载任何内容。"，下面列出它申请的权限 **将服务添加到模型列表**。点 **加载插件**（加载时按钮显示 **加载中…**）。
5. 预期：
   - 提示 **本地插件已加载**。
   - **已安装** 标签里出现 **Magpie Gateway**，版本 0.2.0，名字旁边带 **本地** 标记。
   - 不用重启 Pi-Desktop，服务卡片马上就有（第 4 步里能看到）。

## 第 4 步：在 Pi-Desktop 里填密钥

每张 Magpie 卡片各存一次密钥，填的都是同一个：`magpie-pi-desktop-app`。

1. 打开 Pi-Desktop 的 **设置**，点 **AI 服务**。列表里应该有 **Magpie** 卡片；第 2 步打印的那一行里有 "Magpie 2" 时，还应该有 **Magpie 2** 卡片。它们都带 **插件** 标记，还没存密钥的带 **尚未设置 API 密钥** 标记。
   - **没有这些卡片**：到 **扩展 › 已安装** 确认 Magpie Gateway 是启用的；再在托盘区右键 Pi-Desktop 图标 › **退出 PI-Desktop** › **退出**，重新打开。
2. 点 AI 服务页顶部的 **添加服务**，弹出"添加 AI 服务"窗口。
3. 在 **筛选服务** 框里输入 `magpie`，或在"本地网关"分类下找。这里只列出还没存密钥的卡片，每个下面一行是 `127.0.0.1:3425 · Magpie Gateway`。点其中一个（**Magpie** 或 **Magpie 2**）。
4. 页面显示"由 Magpie Gateway 提供"，服务名和地址已经填好且不能改。只在 **API 密钥** 一栏填入：

   ```
   magpie-pi-desktop-app
   ```

   然后点右上角的 **保存服务**。没填密钥时这个按钮是灰的；保存时显示 **保存中…**。
5. 预期：窗口关闭，提示 **API 密钥已保存**，这张卡片上的 **尚未设置 API 密钥** 消失。
   - 同时提示"该地址没有模型列表。"或"无法获取模型列表。"：密钥已经存上了。模型清单来自插件文件夹，不靠这一次拉取；这个提示只说明当时没连上 Magpie，发消息前先确认 Magpie 在运行。
   - 如果 Pi-Desktop 原来的默认模型用不了，保存时它会把默认模型换成 Magpie 的一个模型；原来的默认模型能用就不动。
6. 还有带 **尚未设置 API 密钥** 的 Magpie 卡片时，从第 2 小步再做一遍，直到每张都存好。
   - 添加窗口里找不到某张卡片：说明它已经存过密钥了，不用再填。

## 第 5 步：在对话里使用

1. 在 Pi-Desktop 左侧点 **新对话**。
2. 点输入框旁边显示当前模型名的按钮，模型菜单会向上弹出。
3. 在 **搜索模型** 框里输入模型名的一部分（例如你在 Codex 里用的那个），点右侧标着 **Magpie** 的那一项。
   - 也可以不搜：在 **最近使用** 下面展开 **其他模型**，在 **Magpie** 或 **Magpie 2** 分组里选。
   - 模型显示的是 Magpie 里的名字，带供应商，例如 `GPT-6 Astra · <供应商名>`；名字以 `· routing group` 结尾的是 Magpie 的路由分组。
   - 选好后把鼠标停在这个模型按钮上，提示是 `模型名 · 推理等级: …`。新对话的推理等级应该是这个模型的默认档位（多数是 high），不是 off。点开菜单能改，可选的档位就是 Magpie 里这个模型支持的那几档。
   - 之前已经开着的旧对话保持它原来的推理等级，要自己改一次，或开新对话。
4. 发一句"你好"，应该正常回复。
5. 打开 Magpie，左侧 **观测** 分组下点 **用量**。**Agent** 一栏里应该出现 Pi-Desktop（也可能显示成它的 id `pi-desktop-app`）。它和 Codex 一样走 Magpie 的多供应商路由、分组和兜底。

## 第 6 步：自检，并确认 Codex 没受影响

1. 自检（只读）。它不打印任何密钥，读 Pi-Desktop 数据库时用的是临时副本，用完就删：

   ```powershell
   cd <本仓库>\packages\pi-desktop
   node --no-warnings scripts\doctor.mjs
   ```

   全部通过时都是 `ok`，没有 `FAIL`（数字以你的为准，有几张卡片就有几行 `… ready`）：

   ```
   ok    Magpie keeps C:\Users\<用户名>\.config\magpie-pi-desktop\plugin\manifest.json: http://127.0.0.1:3425/v1, key magpie-pi-desktop-app, 97 models in Magpie (64), Magpie 2 (33)
   ok    manifest is one Pi-Desktop accepts; 91 models start on a thinking level of their own, 6 have none from Magpie and start on off
   ok    gateway serves the same 97 models to Pi-Desktop
   ok    Pi-Desktop loads Magpie Gateway from C:\Users\<用户名>\.config\magpie-pi-desktop\plugin and reads it again each time it starts
   ok    Magpie ready at http://127.0.0.1:3425/v1: 64 models, as Magpie offers them
   ok    Magpie 2 ready at http://127.0.0.1:3425/v1: 33 models, as Magpie offers them
   ```

   `info` 行只是附加信息，不是错误。出现 `FAIL` 时，按那一行冒号后面的提示做。常见的几种：

   | `FAIL` 那一行的开头 | 意思 | 怎么做 |
   |---|---|---|
   | `Magpie is not keeping …manifest.json` | Pi-Desktop 这一行在 Magpie 里没接入 | 做第 2 步 |
   | `Pi-Desktop has no local.magpie-gateway plugin` | Pi-Desktop 还没加载这个文件夹 | 做第 3 步 |
   | `Pi-Desktop uses its own copy of the plugin` | Pi-Desktop 里装的还是旧的 `.piplug` 版本，它不会跟着 Magpie 变 | 做第 3 步，不用先卸载旧的，密钥会保留 |
   | `the Magpie Gateway plugin is off` | 扩展被禁用了 | **扩展 › 已安装 › Magpie Gateway** 右边的 **⋯** › **启用** |
   | `Pi-Desktop's Magpie has an older model list` | Magpie 已经改好了清单，Pi-Desktop 还没重新读 | 按下面"Magpie 的模型变了之后"第 2 小步做 |
   | `Pi-Desktop has no Magpie 2 provider yet` | 同上：新卡片要等 Pi-Desktop 重新读 | 同上 |
   | `no key saved for Magpie 2` | 这张卡片还没存密钥 | 做第 4 步 |
   | `gateway … not reachable` | Magpie 没在运行 | 打开 Magpie |
2. 确认 Codex 没受影响：

   ```powershell
   cd <本仓库>
   node verify\codex-invariants.mjs snapshot verify\after-connect.json
   node verify\codex-invariants.mjs compare verify\before-connect.json verify\after-connect.json
   ```

   最后一行应是 `OK: no Codex-critical differences`。它检查 Codex 的 `config.toml`、Codex 读的模型目录 `~/.codex/magpie-models.json`、Magpie 的供应商和逐模型设置、Codex 的接入记录、网关给 Codex 的模型数和 `magpie codex` 的输出。
   - 中间的 `info` 行是预期的：`magpieLs: (text changed)`（Pi-Desktop 那一行变成了已接入），以及 `stash.pi-desktop-app…`、`applied.pi-desktop-app…`（Magpie 记下了 Pi-Desktop 的接入）。
   - 出现 `FAIL` 时，先想一下拍快照之后，你有没有自己在 Magpie 里改过 Codex 的模型、effort 或供应商，Magpie 有没有重启或升级过。这些都会让对比报 `FAIL`，和插件无关。

## Magpie 的模型变了之后

在 Magpie 里加减了供应商、增删了模型、改了 `magpie visible pi-desktop-app …`、换了端口之后：

1. **Magpie 这边不用做任何事。** 只要 Agent 页里 Pi-Desktop 这一行是 **已连接**，Magpie 会自己重写 `manifest.json`。这时如果 Pi-Desktop 开着，它会弹一条英文提示 `Reloaded Magpie Gateway`，表示它看到文件变了；模型清单要到下一小步才更新。
2. **让 Pi-Desktop 重新读一遍**，两种做法任选一种：
   - 重启：在托盘区右键 Pi-Desktop 图标 › **退出 PI-Desktop** › **退出**，再打开。只关窗口不够。
   - 不重启：**扩展 › 已安装 › Magpie Gateway** 右边的 **⋯**（"Magpie Gateway 的操作"）› **禁用**，再点一次 **⋯** › **启用**。
   - 平时每天开关 Pi-Desktop 的话，什么都不用做，下次打开就是新清单。
3. 模型多到又多出一张卡片（例如 "Magpie 3"）时，做第 4 步给新卡片填一次密钥。已有卡片的密钥一直保留，换端口也不用重填。
4. 想确认是否已经跟上，跑第 6 步的 `doctor`：全是 `ok` 就是一致的；Pi-Desktop 还没重新读时会报 `Pi-Desktop's Magpie has an older model list`。

几点说明：

- 做不到"Magpie 一改，Pi-Desktop 立刻变"。Pi-Desktop 0.22.0 只在启动、启用插件、加载本地插件这三个时刻读 `manifest.json` 里的服务和模型，插件自己也没有接口去改服务列表。
- 模型可能在卡片之间挪位置（例如从 Magpie 挪到 Magpie 2）。之前用着被挪走的模型的对话，要重新选一次模型。
- 想只留一张卡片，用 `magpie visible pi-desktop-app <模型族/供应商/分组>,…` 把 Pi-Desktop 能看到的模型减到 64 个以内，再让 Pi-Desktop 重新读一遍。
- 行菜单里的 **重载插件** 只重新加载插件的代码，不会更新模型清单。要用上面的 **禁用** 再 **启用**。

## 从旧版本升级

旧版本（0.1.1、0.1.2）是把模型清单打进 `.piplug` 装进 Pi-Desktop，清单是固定的。升级到 0.2.0 只需要三件事，原来存的密钥会保留：

1. **Magpie：让它重新读插件并重新接入。**
   1. 左侧 **扩展 › 插件 › 已安装**，`pi-desktop` 这一行点 **停用**，按钮变成 **启用** 后再点 **启用**。停用时 Magpie 会先断开旧的接入，并撤回它写进旧文件 `connection.json` 的内容。
   2. 左侧 **使用 › Agent**，**Pi-Desktop** 这一行点 **接入**，变成 **已连接**。
   3. 按第 2 步第 4 小步的命令确认 `plugin\manifest.json` 已经写出来。
2. **Pi-Desktop：做第 3 步**（**扩展 › ⋯ › 加载本地插件**，选 `%USERPROFILE%\.config\magpie-pi-desktop\plugin`）。不用先卸载旧的 Magpie Gateway：加载后同一行会变成版本 0.2.0、带 **本地** 标记，**Magpie** 卡片的密钥还在，推理等级马上生效。
3. **给新卡片填密钥**：有 **Magpie 2** 时做第 4 步。然后做第 6 步的 `doctor`。

旧的 `%USERPROFILE%\.config\magpie-pi-desktop\connection.json`、`packages\pi-desktop\dist\*.piplug`、`scripts\pack.mjs` 和 `pi-plugin\` 文件夹都不再使用，留着不影响，也可以自己删掉。

## 第 7 步：撤销（不想用了再做）

1. Pi-Desktop：左侧 **扩展**，**已安装** 标签里找到 **Magpie Gateway** 这一行，点它右边的 **⋯**（"Magpie Gateway 的操作"），选 **卸载**。所有 Magpie 卡片和它们的模型会一起消失。`plugin` 文件夹本身不会被删。
2. Magpie：左侧 **使用 › Agent**，Pi-Desktop 那一行点 **断开**（命令行：`magpie pi-desktop-app default`）。Magpie 会撤回写进 `manifest.json` 的内容。
3. Magpie：左侧 **扩展 › 插件**，**已安装** 标签里 `pi-desktop` 那一行点 **移除**，确认框里再点 **移除**。移除前 Magpie 会自动先断开，所以第 2、3 步顺序反了也没关系。插件文件夹本身不会被删。

只做第 2 步、不做第 1 步时：`manifest.json` 被清空，Pi-Desktop 会保留最后一次读到的 Magpie 卡片和模型（开着时可能弹一条 `Reload failed: Magpie Gateway …`）。要让卡片消失，做第 1 步。

这三步都不碰 Codex。

## 排错

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 插件页有红字 `Agent 没有加载：…` 或 `没有加载成功：…` | `pi-desktop.agent.js` 或 `package.json` 被改坏了 | 按红字内容检查这两个文件；跑一遍下面的开发者自测能定位 |
| 插件 › 已安装 里没有 `pi-desktop` | 插件不在 Magpie 里（被移除了，或从没添加成功） | 按第 1 步"添加插件"重新添加插件文件夹 |
| 插件 › 发现 页没有"已有想装的？"这一栏 | 插件市场列表没加载出来 | 用命令行添加：`magpie plugin add "<本仓库>\packages\pi-desktop"` |
| PowerShell 提示找不到 `magpie` | 新开的窗口里别名没了 | 重新执行 `Set-Alias magpie "<Magpie 安装目录>\magpie.com"` |
| `magpie ls` 里没有 Pi-Desktop | 插件没登记，或 `%USERPROFILE%\.pi-desktop` 不存在（Magpie 靠这个文件夹判断装没装 Pi-Desktop） | 先看 插件 › 已安装 里有没有 `pi-desktop`、有没有红字；打开过一次 Pi-Desktop 这个文件夹就会有 |
| 接入后没有 `plugin\manifest.json`，或 Agent 页这一行还是 **未连接** | Magpie 窗口还在用旧的插件加载结果，或写文件失败 | **扩展 › 插件 › 已安装** 里 `pi-desktop` 这一行点 **停用** 再 **启用**，然后重新 **接入**。还不行就看这一行下面有没有红字，把红字内容记下来 |
| "选择文件夹"窗口里找不到 `.config` | 没在用户文件夹下 | 直接把完整路径 `%USERPROFILE%\.config\magpie-pi-desktop\plugin` 粘贴进地址栏 |
| 加载本地插件时报错，内容里有 `manifest` | 选错了文件夹，或 Magpie 里这一行是断开的（`manifest.json` 是空的） | 确认选的是 `plugin` 文件夹；先做第 2 步让它变成 **已连接** |
| Pi-Desktop 设置里没有 Magpie 卡片 | 扩展被禁用，或 Pi-Desktop 还没重新建服务列表 | 到 **扩展 › 已安装** 确认 Magpie Gateway 已启用；再托盘右键 › **退出 PI-Desktop** › **退出**，重新打开 |
| 发消息提示"请先为此 AI 服务添加 API 密钥。" | 这张卡片没存密钥。每张卡片要各存一次 | 做第 4 步 |
| 提示"无法连接 AI 服务，请检查网络或接口地址。" | Magpie 没运行；或 Magpie 换过端口而 Pi-Desktop 还没重新读 | 打开 Magpie；换过端口就按"Magpie 的模型变了之后"第 2 小步做 |
| 提示"该模型尚未配置，或当前 AI 服务不提供此模型。" | 这个模型在 Magpie 里被隐藏或删除了 | 换一个模型；再按"Magpie 的模型变了之后"第 2 小步让清单更新 |
| Magpie 新加的模型在 Pi-Desktop 里看不到，或删掉的模型还在 | Pi-Desktop 还没重新读 `manifest.json`；或 Magpie 里这一行不是 **已连接**；或 Pi-Desktop 里装的还是旧的 `.piplug` 版本 | 跑 `doctor`，它会说是哪一种 |
| Magpie 的模型推理等级都默认 off，而且每个模型 7 个档位全都能选 | Pi-Desktop 里装的是不带模型清单的旧包（0.1.1） | 做"从旧版本升级" |
| 个别模型推理等级默认 off | 这个模型 Magpie 没给推理等级；或这是之前就开着的旧对话 | 开一个新对话看。`doctor` 第 2 行写着多少个模型没有推理等级 |
| Pi-Desktop 弹出 `Reloaded Magpie Gateway` | Magpie 刚重写了 `manifest.json`，Pi-Desktop 看到了 | 正常。要让新清单生效，按"Magpie 的模型变了之后"第 2 小步做 |
| 想限制 Pi-Desktop 能看到哪些模型 | — | `magpie visible pi-desktop-app <模型族/供应商/分组>,…`，然后让 Pi-Desktop 重新读一遍 |
| 用量页里看不到 Pi-Desktop 的请求 | 密钥填错了。本机网关不会拒绝填错的密钥，请求照样成功，只是记到了别的名下 | 把密钥改成 `magpie-pi-desktop-app` |
| 有些模型的上下文长度显示 128000 | Magpie 没给出这个模型的上下文长度，Pi-Desktop 用了通用默认值 | 不影响使用 |
