# Magpie 扩展点 × Pi-Desktop 能力地图

调研对象：Magpie 0.1.2404、magpie-community/plugins（HEAD 5b1ae40）、Pi-Desktop 0.21.0（Electron 43.6.0，host-core protocolVersion 11）。

## 1. Magpie 插件扩展点

| 扩展点 | 声明方式 | 代表插件 | 本需求是否使用 |
|---|---|---|---|
| Agent（代理接线） | `package.json` 的 `magpie.agent` 指向 `*.agent.js` | aider、pig、kimi-desktop | **使用** |
| Bun 宿主入口 | `package.json` 的 `main`，跑在 Magpie 共享的 Bun 宿主里 | kimi-desktop 的 `index.mjs` | 不需要（见 §4） |
| OpenCode provider/auth | `index.mjs` 的 auth/loader/config/provider 钩子 | workbuddy-auth、zcode-auth | 不需要 |
| 网关中间件 | `magpie.middleware`（`onRequest`/`onEvent`/`onResponse`） | think-tags、你的 magpie-workbench | 不需要 |
| 路由策略 | `magpie.gateway` 导出 `strategies` | reserve | 不需要 |
| 工具 | `tool` 钩子，挂在 `/mcp/magpie/tools` | calc | 不需要 |
| 页面 | `magpie.page` | usage | 不需要 |
| 网关钩子 | `magpie.hooks`（0.1.1273+） | — | 不需要 |

### Agent 插件契约（本插件依赖的部分）
- 描述符 `export const agent = {...}`：在 Magpie 进程内的 moejs 里执行，不能 import，不能用 Node API，加载和 `connect` 各有 1 秒时限。
- 字段：`id`（小写，内置 id 如 `pi` 被保留）、`name`、`icon`、`bin`/`dir`（检测用）、`config`（Magpie 唯一会编辑的文件，`~` 和 `$VAR` 会展开，不存在时自动创建）、`format`（json/yaml/env）、`model`（省略即"仅连接"模式）、`prefix`、`ua`、`notice`、`library`。
- `connect({gateway:{url,v1,key}, models, agent})` 返回"点分键 → 值"，Magpie 写入前把旧值存进 stash；`magpie <id> default` 时逐键还原，原本不存在的键会删掉。
- 仅连接模式下，Agents 页这一行是一个开关；连接期间，新增供应商、插件登录/续期、模型列表变化、Magpie 启动或升级都会重新调用 `connect()`。
- 网关密钥固定为 `magpie-<id>`，本机回环无需注册；Usage、请求日志、按代理匹配的路由规则都按这个 id 归属。
- 检测：`bin` 在 PATH 上，或 `dir` 存在，或 Magpie 已写过 `config`。桌面应用没有 CLI，所以用 `dir`。
- 写入经验：provider 块、模型数组要作为**一个完整对象**返回，否则断开后会残留空父键（pig 的注释、issue #1816）。

## 2. Pi-Desktop 需要对接的能力

| 能力 | Pi-Desktop 的实现 | 对接结论 |
|---|---|---|
| provider 存储 | Rust 进程 `pi-desktop-host-core.exe` 独占 `~/.pi-desktop/pi.sqlite`（WAL、schema v24）与 `secrets/` | 外部不能写；本插件**从不**碰它 |
| 外部写入通道 | 无深链、无 provider CLI 参数；host-core RPC 只走 Electron 的 stdio；可选 MCP 控制服务只读 | 只能走插件 |
| 插件声明 provider | manifest `contributes.providers` + 权限 `provider.register` → host-core 建行 `plugin:<插件id>:<provider id>`，随插件启用/停用，用户不可编辑 | **主路径** |
| provider 字段 | `id`、`name`、`category`/`description`（字符串或 `{en,"zh-CN"}`）、`vendorKey`、`baseUrl`、`apiStyle`（7 种）、`authKind`（api_key/none/oauth）、`models`（≤64，超过时安装报 `declares more than 64 models`；api_key+baseUrl 时可为空） | 没有 headers 字段；baseUrl 和模型清单来自 manifest；一个插件可以声明多个 provider |
| 声明的模型字段 | `id`、`name`（显示名）、`contextWindow`、`maxTokens`、`supportsImages`、`thinkingLevels`、`defaultThinkingLevel`。不在 Pi-Desktop 七个档位里的值会被丢掉，默认档位不在列表里时改用列表第一个 | Magpie 插件的 `connect()` 按 Magpie 的清单生成 |
| 密钥 | 设置 › AI 服务 › 添加服务 › 选插件的服务，填 API 密钥后点"保存服务"，存在 Pi-Desktop 自己的密钥库，"插件拿不到此密钥"。卡片 ⋯ › API 密钥 也能存。每个 provider 各存一次 | 用户填 `magpie-pi-desktop-app` |
| 模型发现 | `GET {baseUrl}/models`，读取 `id`、`display_name`、`context_window`/`context_length`、`max_output_tokens`/`max_tokens`，最多 500 个。只在 manifest 没声明模型时用作模型清单 | 不读 `reasoning_levels`，所以不靠它 |
| 推理等级 | 0.22.0：manifest 声明的模型用它的 `thinkingLevels` 和 `defaultThinkingLevel`。发现来的模型两项都是空的，界面上七个档位全可选，新对话默认 off。只有 Pi-Desktop 自己判定来源是 models.dev 的模型才按内置目录取档位，`custom` 类的插件服务不属于这种 | 0.1.1 把模型留给发现，结果所有 Magpie 模型默认 off；之后改为声明 |
| 更新模型清单 | 声明的清单在 host-core 启动时写进 provider 行，之后发现来的模型不会加进去。同 id 的插件换了来源或版本，已存的密钥保留 | 见下一行 |
| 本地（开发）插件 | *扩展 › ⋯ › 加载本地插件* 选一个文件夹，host-core 记为 `source: dev` 并记下路径，不复制。**每次启动都重新读这个文件夹的 `manifest.json`**，按它重建 provider 行；不重启时，启用插件（含禁用再启用）和再次加载也会重读。Electron 侧监视文件夹，文件一变就重载插件代码并提示 `Reloaded …`，但不通知 host-core，所以 provider 行不变。manifest 读不了时保留上一次的行。`main` 必填，可以指向 `manifest.json` 自己；不认识的顶层键被忽略 | **0.2.0 的主路径**：Magpie 维护这个文件夹，Pi-Desktop 重启后跟上 |
| 插件主进程 API | `pi.plugin/commands/ui/models.list/net/fs…`；没有运行时增改 provider、没有密钥 API、不能改默认模型 | 插件不需要代码，也没法靠代码即时更新 provider |
| 插件文件读取 | `fs.read` 的根只能是 `workspace` 或 `userSelected` | 读不到 `~/.config` 下的文件，所以不靠插件代码去读 |
| 打包格式 | `.piplug` = zip，根目录放 `manifest.json`；`main.js` 为 CommonJS，导出 `onLoad`/`onUnload` | 0.1.x 用过；0.2.0 不打包，直接加载文件夹 |
| 沙箱 | `PI_DESKTOP_DATA_DIR=<目录>` 改数据目录；host-core 可以单独起在临时目录里 | 用来做无 GUI 的安装验证 |
