# 接入配置与验证

插件源码：`packages/pi-desktop/`。目录结构与社区仓库 `packages/<name>` 一致，可以原样放进 magpie-community/plugins 提 PR，市场条目见 `docs/registry-entry.json`。

**发现的行为**：只调用 host-core 的安装接口（`.piplug`）时，provider 行要等 host-core 重启或插件启用时才生成。加载本地插件则马上生成，之后每次启动按文件夹里的 manifest 重建。

**还没在真实环境验证的**（要等在 Magpie 里重新接入后才能看到）：Magpie 把 `connect()` 返回的对象值顶层键整块写入、自动建 `plugin` 子文件夹、以嵌套的 `magpie.apiKey` 判断"已连接"。文档写的是"按键路径逐个写入""文件不存在时会创建"，社区的 pig、kimi-desktop 插件也是这样用的。

**推理等级默认 off 的原因（2026-11-16，Pi-Desktop 0.22.0）**：Pi-Desktop 不读网关 `/v1/models` 里的 `reasoning_levels`。0.1.1 的 manifest 写的是 `models: []`，host-core 就用发现来的模型生成清单，每个模型的 `thinkingLevels` 是空的、`defaultThinkingLevel` 是 null；界面对这种模型给出全部七个档位，新对话取 off。把模型连同 `thinkingLevels`、`defaultThinkingLevel` 声明在 manifest 里，host-core 会原样带进 provider 行。0.1.2 靠 `pack.mjs` 打包时生成这份声明；0.2.0 由 Magpie 插件的 `connect()` 直接写出。

**没能做的**：Magpie 沙箱 CLI。Magpie 应用运行时，CLI 换用其他 `USERPROFILE` 就不输出、不写文件，并返回 0。`verify/magpie-sandbox.sh` 检测到这种情况会跳过，退出码 3。要跑它得先退出 Magpie，而这期间 Codex 没有网关可用，所以没有做。Magpie 那一侧的真实验证放在下面第 2 节，需要你同意后再执行。

**真实安装时发现**：Magpie 0.1.2404 拒绝 Agent id `pi-desktop`，插件页报 `Agent 没有加载：agent id "pi-desktop" is magpie's own agent's`。原因是 Magpie 的会话功能自己用了这个名字，而 CLI 的 Agent 列表里没有它，所以离线调研没发现。0.1.1 改为 `pi-desktop-app`，密钥随之改为 `magpie-pi-desktop-app`。测试里加了 Magpie 自有 id 清单，防止再撞名。

## 2. 真实环境接入

每一步的操作、预期结果和排错见 [04-详细接入教程.md](04-详细接入教程.md)。概要：

1. Magpie：*插件 › 已安装* 里有 `pi-desktop` 这一行，下面写着"把 Pi-Desktop 加到 Agent 页"，没有红字。没有这一行时，在 *插件 › 发现 › 已有想装的？* 选插件文件夹，点"安装"。
2. 先拍 Codex 快照 `node verify\codex-invariants.mjs snapshot verify\before-connect.json`，再在 Magpie 的 *使用 › Agent* 页接入 Pi-Desktop，或执行 `magpie pi-desktop-app provider magpie`。
3. 确认 Magpie 写出了 `~/.config/magpie-pi-desktop/plugin/manifest.json`。
4. Pi-Desktop（只做一次）：*扩展 › ⋯（更多操作）› 加载本地插件*，选 `%USERPROFILE%\.config\magpie-pi-desktop\plugin`，在确认框里点"加载插件"。不用重启。
5. Pi-Desktop：*设置 › AI 服务 › 添加服务*，给每张还没存密钥的 Magpie 卡片（Magpie、Magpie 2…）填 `magpie-pi-desktop-app`，点"保存服务"。
6. 新建对话，选 Magpie 下的模型，发一条消息，在 Magpie 用量页确认归属 Pi-Desktop。
7. 运行 doctor 和 `codex-invariants compare`，确认 Codex 没受影响。

## 3. 日常维护
- Magpie 新增或删除了模型、换了端口：Magpie 自己重写 manifest。Pi-Desktop 下次启动时跟上；不想重启就在扩展页把 Magpie Gateway 禁用再启用。已存的密钥保留；多出新卡片时给它填一次密钥。Pi-Desktop 还没重读时 doctor 报 `Pi-Desktop's Magpie has an older model list`。
- 想限制 Pi-Desktop 能看到的模型：`magpie visible pi-desktop-app <family|provider|group>,…`。减到 64 个以内就只有一张卡片。

## 4. 回滚
1. Pi-Desktop：*扩展* 里卸载 *Magpie Gateway*，Magpie 服务随之消失。用过它的旧会话会回到你选择的其他服务。
2. Magpie：Agent 页断开 Pi-Desktop（`magpie pi-desktop-app default`），再在插件页移除它。移除时 Magpie 也会先自动断开。
3. 再跑一次 `codex-invariants compare`，确认 Codex 部分与基线一致。

## 5. 零代码备选
不装任何插件：在 Pi-Desktop 的 *设置 › AI 服务 › 添加 › 使用自定义端点* 里，Base URL 填 `http://127.0.0.1:3425/v1`，密钥填 `magpie-pi-desktop-app`，接口格式选 Chat Completions。效果是一样能调用 Magpie 的模型。区别有两点：一是没有 Pi-Desktop 代理行，Magpie 不会把它当作已知代理，也就没有可见模型控制，用量只按密钥名记；二是 provider 可以在 Pi-Desktop 里手动编辑。
